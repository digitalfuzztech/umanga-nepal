## Validation and public contract

| Rule                         | Implementation                                                                                                        |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| IDs                          | UUID validation; UUID v4 generated by `crypto.randomUUID()` on create.                                                |
| Slug                         | Trimmed, required, 1-191 characters; `^[a-z0-9]+(?:-[a-z0-9]+)*$`; unique within its table.                           |
| Title                        | Trimmed, required, 1-255 characters, unrestricted human Unicode/Nepali/emoji.                                         |
| Category                     | Trimmed, required, 1-100 characters; no rigid enum.                                                                   |
| News excerpt / Event summary | Trimmed, required, 1-5,000 characters.                                                                                |
| News content                 | Trimmed at outer edges only, required, up to 200,000 characters; plain text; internal paragraph separators preserved. |
| News editorial date          | Required real `YYYY-MM-DD` calendar date; no createdAt/today substitution.                                            |
| Event start                  | Required real `YYYY-MM-DD` calendar date; string-mode SQL DATE; no local datetime conversion.                         |
| News location                | Optional/nullable, trimmed, up to 255 characters; blank becomes NULL.                                                 |
| Event location               | Required, trimmed, 1-255 characters; Unicode accepted.                                                                |
| registrationOpen             | Boolean, default false on create; independent of chronology.                                                          |
| demoContent                  | Boolean, default false on create.                                                                                     |
| published                    | Boolean, default true on create.                                                                                      |
| sortOrder                    | Nullable signed MariaDB INT; blank becomes NULL.                                                                      |
| Unknown metadata             | Strict Zod objects reject unsupported fields, including client image URLs/keys, ID and createdAt.                     |
| Metadata edits               | Partial patches merged with locked existing metadata; omitted fields preserved. Title does not generate/change slug.  |
| Image                        | Existing signature validation for JPEG/PNG/WebP, nonzero, <=8 MB; File-to-Buffer only on server.                      |

Common slug/date/sort-order/duplicate-error validators are shared narrowly; News and Event CRUD remain distinct modules. Friendly duplicate prechecks supplement authoritative MariaDB unique constraints; nested driver duplicate errors map to `SLUG_ALREADY_EXISTS` without SQL disclosure.

Safe errors include `UNAUTHORIZED`, `INVALID_NEWS_DATA`, `INVALID_EVENT_DATA`, `SLUG_ALREADY_EXISTS`, `NOT_FOUND`, `UNABLE_TO_LOAD`, `SAVE_FAILED`, `UPDATE_FAILED`, `DELETE_FAILED`; News additionally handles invalid/oversized images, storage configuration and upload failures. Bridges return safe structured failures; public bridges throw generic availability errors.

## Queries, ordering and event-bar semantics

News admin queries: `getNewsForAdmin()` and `getNewsById(id)` require current admin authentication. Full admin rows include storage references for server/admin operations. Item lookup returns null when absent.

News public queries: `getPublishedNews()` and `getPublishedNewsBySlug(slug)` use explicit public columns and SQL `published=true`. Unknown, invalid and unpublished slugs return null. Public fields: ID, slug, title, excerpt, content, category, location, image URL, newsDate, demoContent, sortOrder, createdAt. No imageStorageKey or updatedAt.

News ordering: defined sortOrder first, ascending sortOrder, descending newsDate, descending createdAt, ascending ID.

Event admin queries: `getEventsForAdmin()` and `getEventById(id)` require auth. Public `getPublishedEvents()` uses SQL publication filtering and explicit public fields: ID, slug, title, summary, category, eventStart, location, registrationOpen, demoContent, sortOrder, createdAt.

Event list ordering: defined sortOrder first, ascending sortOrder, ascending eventStart, descending createdAt, ascending ID. This permits later migration to preserve the static manual array order.

No Event public-by-slug helper was added: the audit confirms no current Event detail route requires one. Stable Event slugs remain fully supported in admin CRUD.

`getNearestEligibleEvent()` performs a bounded SQL query: published only, eventStart >= current Kathmandu calendar date, date ascending, then defined/ascending sortOrder and ID for ties; limit 1. Today is eligible. Registration state has no effect. This matches the current Header bar's date eligibility and nearest-date selection, without relying on stale static labels. No caller/browser date override is accepted. Date-derived chronology will be used at future public cutover; public pages remain static now.

Admin/public bridges use createServerFn and dynamic server-only imports. News create/replacement accept real FormData/File; Event create/update accept strict structured metadata. No bridge is connected to a public route or admin placeholder in this phase.

## Mutation and media architecture

- News create: authenticate, validate metadata, friendly slug check, validate/upload image with the existing storage abstraction, verify remote existence and public HTTPS image response, generate/save UUID row, read back inside transaction.
- Media keys use `news/YYYY/MM/UUID.jpg|png|webp`; browser filenames/paths/URLs are not authoritative.
- DB insert failure after verified upload deletes the new object. Cleanup failure logs a safe warning.
- News metadata update locks the row and updates only allowed metadata. Image references and createdAt are preserved.
- Image replacement uploads/verifies first, then locks/updates image fields in a transaction; detects concurrently changed image references. DB failure removes new media. Only after DB success does old-media cleanup run. Old cleanup failure returns `cleanupWarning=true` without undoing the saved image.
- News delete locks/removes the DB row transactionally, then removes the current media; cleanup failure is a non-fatal warning.
- Event create validates and inserts/reads within a transaction; update locks and merges metadata; delete locks/removes the row. No media work.
- Admin lists/lookups and all mutations require existing admin auth. Public list/by-slug/nearest helpers are publication-safe. No browser-supplied admin identity.
